# Updated TTS Service Role (with ElevenLabs)

## Core Responsibility

The TTS Service:

1. Subscribes to MongoDB `tts_queue` collection (Change Streams)
2. Sends text to ElevenLabs API
3. Receives streaming or generated audio
4. Plays audio into PulseAudio `virtual_mic`
5. Updates MongoDB status

Higher latency

# TTS Service Internal Modules

---

## Module 1 — MongoDB Change Stream Listener

Listens for new TTS tasks.

Example:

```python
change_stream = db.tts_queue.watch([
  {"$match": {"operationType": "insert"}}
])

async for change in change_stream:
    text = change["fullDocument"]["text"]
    await speak(text)
```

---

## Module 2 — ElevenLabs Client

Streaming example:

```python
import requests

url = f"https://api.elevenlabs.io/v1/text-to-speech/{VOICE_ID}/stream"

headers = {
  "xi-api-key": API_KEY,
  "Content-Type": "application/json"
}

data = {
  "text": text,
  "model_id": "eleven_multilingual_v2"
}

response = requests.post(url, headers=headers, json=data, stream=True)
```

This returns audio chunks.

---

## Module 3 — PulseAudio Output Writer

Write PCM directly:

Example:

```python
import sounddevice as sd

stream = sd.OutputStream(
    samplerate=16000,
    channels=1,
    device="virtual_mic"
)

stream.start()

for chunk in audio_chunks:
    stream.write(chunk)
```

This injects audio into meeting.
